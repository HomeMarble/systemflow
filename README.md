# هوم ماربل ERP — المرحلة الثانية + الإضافات
**المصنع والمشتريات والمستودع والقياسات والتركيبات وفحص الجودة + الدعم الفني والدردشات واستيراد Excel وحفظ التقارير والنسخ الاحتياطي**

هذه النسخة = المرحلة الأولى كاملة + إضافات المرحلة الثانية. لم يُحذف أي شيء من المرحلة الأولى.

---

## 1) خطوات التشغيل (مرة واحدة فقط)

1. افتح مشروعك في Supabase / Lovable Cloud ← **SQL Editor**.
2. الصق محتوى الملف `database/phase2_migration.sql` كاملاً، ثم اضغط **Run**.
   - الملف **إضافي فقط**: لا يحذف ولا يعدّل أي جدول أو بيانات من المرحلة الأولى.
   - تشغيله أكثر من مرة آمن (Idempotent).
3. بعده الصق محتوى الملف `database/extras_migration.sql` كاملاً، ثم اضغط **Run** (نفس قاعدة البيانات، إضافي فقط وآمن للتكرار).
4. من **Database ← Replication / Realtime** تأكد أن Realtime مفعّل (الملف يضيف الجداول تلقائياً لقناة `supabase_realtime`).
5. ارفع مجلد `homemarble/` مكان النسخة القديمة. لم يتغيّر `config.js`، فهو نفس الاتصال.
6. من صفحة **المستخدمون والصلاحيات** فعّل الأدوار الجديدة للموظفين، ومنها دور **الدعم الفني**.

> إن فتحت النظام قبل تشغيل ملف SQL، فستعمل المرحلة الأولى بشكل طبيعي، وتظهر رسالة تطلب تشغيل الملف.

## 2) الأدوار الجديدة

| الدور | ما يراه / يفعله |
|---|---|
| المشتريات | طلبات الشراء، الموردون، المخزون، إرسال الطلب للمورد، الاستلام |
| أمين المستودع | الأصناف، حركات الوارد والصرف والتسوية، الحجز والصرف للطلبات، الاستلام |
| مشرف القص / التجميع / التلميع | لوحة المصنع، ونقل المنتجات **من مرحلته فقط** |
| مراقب الجودة | فحص ومعاينة المنتجات، والاعتماد أو الرفض مع الصور |
| فني القياسات | زياراته المسندة إليه، ورفع المقاسات والصور والملاحظات |
| فريق التركيبات | مهامه، وتحديث الحالة، وصور قبل وبعد، وتوثيق تسليم العميل |
| **الدعم الفني** | قسم الدعم الفني: طلبات نسيان كلمة المرور وتعيين كلمة مرور جديدة، ومحادثات الزوار والرد عليها |

الأدوار القديمة (مدير النظام، المدير التنفيذي، المبيعات، مدير المصنع، المحاسبة) تحتفظ بكل صلاحياتها، ويُضاف لها ما يناسبها من المرحلة الثانية.

## 3) ميزات المرحلة الثانية (حسب عرض السعر)

### واجهة مدير المصنع ومشرفي القص والتجميع والتلميع
- لوحة Kanban بالمراحل: بانتظار البدء ← القص ← التجميع ← التلميع ← فحص الجودة ← جاهز ← تم التركيب.
- **حالة كل منتج داخل الفاتورة الواحدة**: عند إرسال الطلب للمصنع تُنشأ البنود تلقائياً من الفاتورة أو العقد أو عرض السعر.
- بدء وإيقاف مؤقت ونقل للمرحلة التالية، وإرجاع لمرحلة سابقة مع ذكر السبب، وسجل إنتاج زمني لكل منتج.
- مواعيد تسليم، وتنبيه بالمنتجات المتأخرة، وطباعة **بطاقة تشغيل** PDF.

### طلبات المشتريات
- الموردون، والتكلفة (تُحسب تلقائياً)، والأولوية، وتاريخ التوريد المتوقع.
- مسار الحالة: مسودة ← بانتظار الاعتماد ← معتمد ← أُرسل للمورد ← توريد جزئي ← تم التوريد.
- **الارتباط بفاتورة العميل** (الطلب والعميل).
- الاستلام الكلي أو الجزئي يضيف الكميات للمخزون تلقائياً، وطباعة **أمر شراء** PDF.

### المستودع والمخزون
- الأصناف والكميات وتكلفة الوحدة والموقع والمورد الافتراضي.
- **المواد المحجوزة** لكل طلب، و**الكمية المتاحة فعلياً** = الرصيد − المحجوز.
- **الحد الأدنى**: تمييز الأصناف التي وصلته مع تنبيه، وزر **«طلب شراء»** يُنشئ طلباً جاهزاً بالكمية المقترحة.
- حركات وارد وصرف وتسوية جرد، وسجل كامل لها.

### واجهة فني القياسات
- جدول الزيارات (اليوم والقادمة) وإسناد الفني.
- رفع المقاسات (عرض، طول، عمق، عدد)، وصور الموقع، والملاحظات.
- طلب القياس من المبيعات (المرحلة الأولى) يتحول إلى **«منفّذ»** تلقائياً عند انتهاء الزيارة.
- طباعة **تقرير الزيارة** PDF، وزر لفتح الموقع على الخريطة.

### واجهة فريق التركيبات
- جدولة المواعيد مع عرض أسبوعي، وقائد الفريق والأعضاء.
- تحديث الحالة: في الطريق ← جاري التركيب ← تم التسليم.
- **توثيق الصور** قبل التركيب وبعده.
- **تسليم العميل**: اسم المستلم وجواله وتقييمه وإقراره. بعدها يصبح الطلب «مكتمل» تلقائياً.
- طباعة **أمر تركيب** أو **محضر تسليم** PDF.

### فحص الجودة والمعاينة قبل اعتماد الجاهزية
- قائمة معاينة من 6 بنود: المقاسات، اللون والعروق، التلميع، الحواف، التجميع، التغليف.
- **لا يُعتمد أي منتج كجاهز إلا بعد اجتياز الفحص**، وهذا مفروض في قاعدة البيانات نفسها.
- المنتج المرفوض يعود تلقائياً لمرحلة الإصلاح ويُحتسب عدد مرات الإعادة.
- عندما تجتاز كل منتجات الطلب الفحص، تتحول حالة الطلب إلى «جاهز للتركيب» تلقائياً.

### الربط مع المرحلة الأولى
- لوحة المدير التنفيذي: قسم جديد بمؤشرات المصنع والمخزون والمشتريات والتركيبات.
- الجرس والتنبيهات: تنبيهات جديدة حسب دور كل موظف.
- البحث العام: يشمل الأصناف وطلبات الشراء والزيارات والتركيبات.
- ملف العميل وصفحة الطلب وصفحة طلب القياس: أقسام تشغيل جديدة **تُضاف أسفل** المحتوى القديم.
- سجل العمليات: يشمل كل عمليات المرحلة الثانية بأسماء عربية.
- التحديث اللحظي: يشمل كل الجداول الجديدة.

## 3-ب) الإضافات الجديدة

### قاعدة البيانات نفسها (Lovable Cloud) — تحديث لحظي
- لم يتغيّر `config.js`: نفس الرابط والمفتاح. أي إضافة أو تعديل أو حذف تظهر فوراً لكل المستخدمين والزوار في أي دولة (Realtime + تحديث تلقائي احتياطي).

### نسيت كلمة المرور ← قسم الدعم الفني
- في شاشة «نسيت كلمة المرور» يكتب الزائر **بريد الحساب** + **رقم الجوال/الواتساب أو البريد** الذي سيتواصل عليه الدعم.
- يظهر الطلب فوراً في **الدعم الفني ← طلبات كلمات المرور**. الموظف يتحقق من الحساب، ويولّد كلمة مرور جديدة ويعيّنها بضغطة، ثم يرسلها بالواتساب أو الاتصال أو البريد مباشرة من الشاشة، ويغلق الطلب.
- حماية: موظف الدعم لا يستطيع تغيير كلمة مرور حساب إداري (فقط مدير النظام). حد أقصى للطلبات لمنع الإزعاج.
- خيار رابط الاستعادة بالبريد الأصلي ما زال موجوداً تحت «طرق أخرى».

### دردشة الزوار مع الدعم الفني
- زر عائم «الدعم الفني» يظهر للزوار (حتى بدون حساب) ولمن ينتظر التفعيل. يكتب الاسم ووسيلة التواصل والرسالة.
- المحادثة تظهر فوراً عند الدعم الفني مع عدّاد الرسائل غير المقروءة، ويرد الموظف، ويصل الرد للزائر خلال ثوانٍ.
- المدير يعيّن دور «الدعم الفني» من صفحة المستخدمين.

### استيراد العملاء من Excel / CSV
- في صفحة العملاء: زر **استيراد Excel** (يقبل xlsx / xls / csv) — مثلاً 1000 عميل دفعة واحدة.
- تعرّف تلقائي على الأعمدة (الاسم، الجوال، البريد، المدينة، العنوان، الفرع، ملاحظات) مع إمكانية تعديل الربط، ومعاينة قبل الحفظ.
- كشف التكرار بالجوال/البريد: تخطّي أو تحديث أو إضافة. قالب Excel جاهز للتحميل، وزر **تصدير** للعملاء.

### حفظ التقارير قبل الحذف أو التصدير
- زر **حفظ التقرير** أعلى كل صفحة: يلتقط المؤشرات والجداول المعروضة ويحفظها كـ:
  - ملف **Excel**، أو ملف تقرير **.hmr** يمكن فتحه لاحقاً داخل النظام للمراجعة، أو طباعة/PDF، أو حفظه في **أرشيف التقارير** على السحابة.
- صفحة **التقارير والنسخ الاحتياطي**:
  - فتح أي ملف .hmr أو Excel محفوظ وعرضه.
  - **نسخة احتياطية كاملة** (.hmbak أو Excel) لكل بيانات النظام، و**استعادة** منها (اختيار الأقسام).
  - **سلة المحذوفات**: كل سجل يُحذف يُحفظ تلقائياً مع ما حُذف معه، ويمكن استعادته بضغطة.

### الدردشات بالكود
- المدير أو المدير التنفيذي ينشئ دردشة فيُولَّد **كود** (6 أحرف) ورابط مباشر.
- أي شخص (موظف أو زائر) يكتب الكود في «دخول دردشة بالكود» أو يفتح الرابط، يدخل الدردشة فوراً.
- الإدارة تتابع كل الدردشات، وتغلقها أو تعيد فتحها أو تحذفها، مع مدة صلاحية اختيارية.

## 4) الضوابط المفروضة في قاعدة البيانات
- لا جاهزية بدون اجتياز فحص الجودة.
- كل مشرف ينقل المنتجات **من مرحلته فقط**، وتعديل بيانات البند من صلاحية مدير المصنع فقط.
- لا يتغيّر الرصيد إلا عبر حركة مخزون، ولا صرف بأكثر من الرصيد، ولا حجز بأكثر من المتاح فعلياً.
- اعتماد طلب الشراء من صلاحية الإدارة أو مدير المصنع أو المحاسبة، ولا إرسال للمورد قبل الاعتماد.
- لا استلام بأكثر من الكمية المتبقية.
- لا بدء أو إغلاق تركيب قبل جاهزية كل المنتجات، ولا إغلاق بدون اسم المستلم وصورة بعد التركيب.
- الفني وفريق التركيب يعدّلون فقط المهام المسندة إليهم.
- الصور محفوظة في Bucket خاص `hm-files`، ولا يفتحها إلا الموظفون عبر روابط مؤقتة.

| `js/extras.js` | **ملف جديد**: الدعم الفني، الدردشات، الاستيراد والتصدير، التقارير، النسخ الاحتياطي |
| `database/extras_migration.sql` | **ملف جديد**: جداول ودوال وصلاحيات الإضافات + Realtime |

## 6) الاختبارات التي تمت
- **قاعدة البيانات (PostgreSQL 17)**: تشغيل الملف على مخطط المرحلة الأولى ثم إعادة تشغيله، واختبار كل الضوابط والصلاحيات (نجاح ورفض) عبر الدورة الكاملة: بيع ← مصنع ← جودة ← مخزون ← شراء ← قياس ← تركيب ← تسليم.
- **الواجهة**:
  - تطابق حرفي لكل صفحات المرحلة الأولى بين النسخة الأصلية والجديدة.
  - التأكد من عدم فقدان أي نص أو زر من المرحلة الأولى بعد تفعيل المرحلة الثانية.
  - عرض كل الصفحات للأدوار الـ13 بدون أخطاء.
  - اختبار الصلاحيات والنماذج والطباعة.
  - التأكد من أن النظام يعمل بأمان قبل تشغيل ملف SQL.
- **الإضافات**: اختبار قاعدة البيانات للزائر والدعم الفني والمبيعات والإدارة (طلبات كلمة المرور، تعيين كلمة المرور، محادثات الزوار، الدردشات بالكود، سلة المحذوفات والاستعادة الكاملة)، واختبار الواجهة لكل الأدوار وشاشات الزوار، مع تطابق صفحات المرحلتين الأولى والثانية.
